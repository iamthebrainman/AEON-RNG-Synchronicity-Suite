# ESP32 Firmware for AEON

This folder contains a reference firmware for ESP32 nodes (`aeon_rng_node.ino`) and tools to generate that firmware from the host application.

## Overview
- Each ESP32 node sends UDP packets to the AEON host. Packets are structured as:
  - Header: NodeID (4 bytes, little-endian) + SeqNum (4 bytes, little-endian)
  - Payload: random bytes generated by `esp_random()` (default payload in template: 256 bytes)
- Host listens on UDP port **5000** by default.

## Generating & Flashing
- From the GUI: Menu → "Generate ESP32 Firmware..."
- From the command line:
  ```powershell
  python firmware_gen.py <SSID> <PASSWORD> <HOST_IP>
  # Example:
  python firmware_gen.py "MyHomeSSID" "SecretPass" 192.168.1.42
  ```
- The generated .ino file will be written to `esp32_firmware/aeon_rng_node/aeon_rng_node.ino` — open and flash with the Arduino IDE (ESP32 board package required).

## Recommended Settings & Troubleshooting ⚠️
- Use a stable Wi‑Fi network; avoid public/guest networks.
- Reserve a DHCP lease for the node in your router (or set a static IP) to avoid IP changes.
- Disable client/AP isolation (sometimes called "Wireless Isolation" or "AP Isolation").
- If packets appear to be lost frequently:
  - Check router logs and reduce network congestion.
  - Increase host UDP receive buffer (`SO_RCVBUF`) or reduce payload rate (change `PAYLOAD_SIZE` or `delay()` in `loop`).
  - Ensure firewall/antivirus on the host allows incoming UDP on the selected port.
- The firmware already disables Wi‑Fi power save (`WiFi.setSleep(false)`) and attempts to connect to a specific BSSID/channel when present — these help on some routers but are not guaranteed.

## Debugging Tips
- Use `Serial` logging in the Arduino IDE (115200 baud) to see connection and packet transmission logs.
- Test the host listener using the included `test_udp_sender.py` script; start the AEON visualizer and run the test sender to confirm host-side receipt.
- If you see "NO ESP32 DATA" in the UI: the host's listener isn't receiving new packets; verify network reachability and firewall first.
